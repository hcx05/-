# 工具

## 檢查.py
專案一致性檢查,於專案根目錄執行:

```
python3 工具/檢查.py
```

有問題時列出清單並以結束碼 1 結束;全部通過則輸出「全部檢查通過」。

| 檢查項目 | 內容 |
|---|---|
| 連結 | 所有 Markdown 相對連結是否有效 |
| 感情對稱 | A 對 B 有紀錄,B 對 A 也要有;對方已故者不需對稱;標「尚未接觸」者略過 |
| 戰力 | `角色/`、`狀態/` 內不得出現超過 L25 的戰力;狀態表 L 與第一部設定一致 |
| 事件 | 事件 ID 連號;出場角色必有角色資料夾 |
| 事件覆蓋 | 事件的出場者,其記憶檔必須列出該事件 ID |
| 已故 | 已故角色不得出現在死亡事件之後的事件(以最新狀態快照的「已故(PRO-xxx)」為準;同卷以時間線的序比較先後,後加入的事件編號不依時間) |
| 本卷內死亡 | 年齡表標「已故(本卷事件)」者,不得出現在晚於死亡事件的出場名單(序卷、第一部、第二部、第三部皆檢查) |
| 伏筆 | 伏筆登記簿引用的事件必須存在 |
| 占比 | 各部宏觀大綱宣告的同行章占比須達下限(第一、二部 39.5%、第三部 46%,DEC-086);實測核對見劇情量化 D4 |
| ID | `設計規範/ID對照.md` 的 ID 唯一、路徑存在、檔案內的 ID 一致;角色、勢力、場景資料夾皆已登記 |
| 術語 | 術語表「避免寫法」不得出現在其他文件 |
| 年齡 | 年齡表與角色狀態的年齡一致 |
| 戰力 | 戰力基準人物表與狀態表的 L 一致 |
| 個性 | 個性轉變的觸發事件必須存在且角色為出場者;狀態表須有「當前個性」欄 |
| 完成度 | 已開發的卷(有事件描述者)必備檔案齊全:卷大綱、時間線、節奏檢視、吸引力分析、年齡表、章節索引;卷末快照四份、知情矩陣、伏筆登記簿只在該卷已開始收尾(有 `狀態/{卷}結束/`)時要求 |
| 章節 | 章節大綱的「對應事件」與事件描述的「章節」欄一致,每個事件都被某章涵蓋(已有事件描述的卷皆檢查,含第一部) |
| 章節(三種去向) | 事件描述的章節欄可為「第 N 章」(演出,須列在該章大綱的「對應事件」)、「第 N 章(提及)」(須列在該章大綱的「提及事件」)、「背景」(不得被任何章節大綱列入);用於序卷三章版(DEC-073) |
| 正文 | `正文/{卷}/第N章_標題.md` 的章號、標題、對應事件須與章節大綱一致,且列入 `正文/README.md` 的進度表(階段 G 關卡) |
| 事件描述 | 已有事件描述的卷:每個事件與時間線的序號、時間、章節、標題一致;描述不超過 120 字;出場角色、勢力與場景須與凍結紀錄一致 |
| 招式錄 | `武學設定/招式/{卷}招式錄.md` 每列的事件 ID 須在凍結紀錄、出場者須在該事件的出場名單、事件章節須落在所屬小節的章節區間;`套路錄.md` 標「已出場」的事件 ID 須出現在招式錄 |
| 年齡(第一部) | 第一部年齡表起點須等於序卷年齡表結束;各角色 `設定/第一部.md` 的年齡須等於年齡表起點;時間線男女主歲數須等於「起點 + 初遇後滿年數」 |
| 缺口 | 已結案的卷(缺口掃描標「狀態:已結案」):凍結紀錄的出場角色、勢力、場景都必須有檔案,或登記為待建 |
| 凍結 | 已有凍結紀錄(`凍結.md`)的卷:時間線每個事件須在凍結紀錄中,且相對時間與章節一致;事件 ID 不得刪除 |
| 時間線 | 已建立時間線的卷:事件 ID 前綴正確且連號,卷大綱每一章至少有一個事件,時間線不得引用卷大綱沒有的章 |
| 大綱 | 卷大綱(`故事線/{卷}/大綱.md`)每章的線別須與宏觀大綱(`故事大綱/`)一致,章數相同 |

| 標籤 | 時間線的事件標籤與感情線必須在標籤表登錄;感情線只填狀態詞;節奏檢視須為最新(標籤仍含「待填」的卷不檢查) |

## 標籤檢視.py
依時間線產生節奏檢視(`故事線/{卷}/節奏檢視.md`),提供兩個視角:事件標籤節奏、男女主感情線弧線,並列出提醒(連續重事件缺緩衝、爭執或分離缺收束、緩衝占比過低)。

```
python3 工具/標籤檢視.py [卷資料夾,預設 故事線/序卷]   # 例:python3 工具/標籤檢視.py 故事線/第一部
```

## 擴充到其他卷
- 第一部以後的事件前綴為 `P1-`、`P2-`、`P3-`,呼叫 `check_events(volume='第一部', volume_dir='故事線/第一部', prefix='P1')`。
- 每卷完成後新增 `狀態/{卷}結束/`,檢查腳本會以最新一份快照為準;快照的先後依卷序(序卷、第一部、第二部、第三部),不用字串排序(「二」的碼點大於「三」,曾使第三部快照被略過,見 DEC-067)。

## 缺口掃描.py
依 `故事線/{卷}/凍結.md` 的出場者表列出缺口(缺角色資料夾、缺該卷設定、缺勢力檔、缺場景建模),已登記於場景設定 README「待建」的場景不算缺口。階段 B1 使用。

```
python3 工具/缺口掃描.py [卷名,預設 第一部]
```

## 出場順序
| 檢查 | 說明 |
|---|---|
| 出場順序 | `python3 工具/出場順序.py 故事線/{卷}` 產生 `出場順序.md`。護欄:單一事件首次登場的新名字 ≤ 2、單章 ≤ 4;相隔 12 章以上再出現者,中間章節的「群像補充」須有「回頭提示」;檔案過期即報錯。男女主與前卷已出場者不計入新名字 |

## 單次出場角色
| 檢查 | 說明 |
|---|---|
| 單次出場 | 某卷事件描述中只在一個事件出場的角色(男女主除外),不得有該卷的記憶、武學、個性、感情紀錄 |

## 階段 D 閘門
`故事線/{卷}/紀錄對照.md` 標「狀態:已結案」後啟用:事件覆蓋(事件出場者的記憶檔須列出該事件 ID)、感情對稱、個性轉變(觸發事件存在且角色為出場者)、成長檔不得殘留「(待填)」。已故檢查亦涵蓋跨卷:前一卷已故者不得出現在本卷任何事件。

## 章節包.py
階段 G1:把寫一章正文需要的資料,依「限知」原則組成一份 Markdown 上下文包。只讀,不改任何專案檔案;每次現組,不存檔、不提交,所以不會過期。

```
python3 工具/章節包.py 第一部 3                 # 輸出到標準輸出
python3 工具/章節包.py 第一部 3 --out 檔案.md    # 寫成檔案(放在專案之外或暫存區)
```

包內各節與來源:章節大綱;對應事件與提及事件(事件描述);前章銜接(前章大綱的「結尾與銜接」、已寫成時的前章正文末 1200 字;前章正文尚未寫成時改帶前章大綱的「情節要點」與「注意事項」供逐項對齊;前兩章的章末狀態摘要);出場者的卷初狀態(上一卷結束的角色狀態);秘密知情(上一卷結束時點的知情矩陣,只留出場者欄);出場角色的設定、與本章事件相關的記憶與個性;場景建模;相關伏筆;本章招式;事實登錄中提到本章角色或場景的條目;術語表「避免寫法」;本卷已登記的正文補充;文風錨點。

限知:狀態與知情矩陣取「上一卷結束」,不取更晚的時點;事件只取本章的;主角的「價值觀變化方向」(全書弧線)不放進包。序卷沒有前卷快照,以大綱與角色設定為準。資料缺漏處寫「(無)」,不補內容。包與正本不一致時以正本為準。

## 句式掃描.py
階段 G2.1:對 `正文/` 下的章節檔計算 [寫作規範](../正文/寫作規範.md) 第三節列的句型與高頻詞密度(每萬漢字),比較相鄰章,並列出章內反覆的短語(已遮人名)、非對白段首字的集中度與首末段。**只列提示,結束碼恆為 0**,依規範第九節「自動偵測只是提示,不是文學上的通過或失敗判決」。

```
python3 工具/句式掃描.py                 # 掃 正文/ 下所有 第N章_*.md
python3 工具/句式掃描.py 正文/第一部      # 掃指定資料夾
python3 工具/句式掃描.py 檔案1.md 檔案2.md
```

「提示門檻」在檔內的 `FLAG`,是起點值,依實際章節調整。「三連同字起句」常抓到正常的列舉,要看例句再判斷。沒有章節檔時只印說明。

## 劇情量化.py
把劇情當成系統量測,回答「夠不夠好」。只讀。指標定義、證據等級與驗收標準的正本是 [劇情基準](../設計規範/劇情基準.md);本工具只讀取其中的「基準區間(機器讀取)」。

```
python3 工具/劇情量化.py                  # 報告印到標準輸出
python3 工具/劇情量化.py --out 檔案.md     # 寫成檔案(不提交,需要時現產生)
python3 工具/劇情量化.py --strict         # 有硬不變量違反時結束碼為 1(預設恆為 0;H5 為男女主同行比例,DEC-086)
python3 工具/劇情量化.py --裁定表         # 印出 DEC-074 逐章裁定的工作表
```

指標分組:A 規模與容量;B 耦合與依賴(角色共現圖);C 狀態管理(秘密何時得知、伏筆距離);D 負載與節奏(事件類型比例、最長連續無緩衝段、視角平衡、D4 男女主同行與分離〔同行章、窗口外最長連續無同場章、男女主在場率,門檻為專案自訂,DEC-086〕、尾段密度);E 難度曲線;F 需求符合度(DEC-074 朝堂傾向);G 改編就緒度(事件契約欄位、場景與角色視覺資料);H 硬不變量(伏筆有設置、有回收、不早於設置;待決表清空)。

與 `檢查.py` 的分工:`檢查.py` 管連結、年齡、感情對稱、已故、凍結等結構一致性;本工具管「結構之上」的量測與驗收,尤其是 `檢查.py` 沒涵蓋的伏筆因果順序與待決表。
朝堂傾向的判定規則是啟發式,在檔案頂端的 `COURT_*` 常數可調;沒有基準證據的指標只列數字,不下判斷。

## 代價帳.py
量測主角的「代價分布」。只讀。資料正本是 [代價帳](../狀態/代價帳.md)(人工依事件描述填寫,逐項標依據);基準區間讀 [劇情基準](../設計規範/劇情基準.md) 的 J1。

```
python3 工具/代價帳.py            # 報告(只是提示)
python3 工具/代價帳.py --strict   # 帳本格式有誤時結束碼為 1(J1 超出門檻只是提示)
```

- J1:男女主任一承擔不可逆損失的章之間,最長空窗(全書章序);
- J2:標籤帶死亡、悲劇的演出事件有帳目的比例,並列出沒帳目的候選(分成「整章都沒有」與「同章已有」);
- J3:損失的類別與可逆性分布。

帳本格式(事件 ID 存在、類別與可逆性在詞表內、承擔者是出場者或註明不在場)由 `檢查.py` 同步檢查。帳本是草案,覆蓋不全會讓 J1 偏高。

## 體驗模擬.py
推估體驗者在每一章的狀態(劇情基準 K 組)。只讀。輸入是時間線、事件描述、伏筆登記簿、[讀者知情](../狀態/讀者知情.md)、代價帳與 [體驗參數](../設計規範/體驗參數.md)。

```
python3 工具/體驗模擬.py                 # 完整報告(K1 至 K7)
python3 工具/體驗模擬.py --out F.md       # 寫成檔案
python3 工具/體驗模擬.py --csv F.csv      # 另存逐章數列(供畫圖)
python3 工具/體驗模擬.py --draws 100      # 改蒙地卡羅抽樣次數
python3 工具/體驗模擬.py --自測           # 用已知答案的小資料檢查各函式
```

- K1 讀者知情:戲劇反諷與謎團庫存;K2 開放問題庫存;K3 記憶保留(伏筆、角色重返);K4 事件索引轉換負荷;K5 效價/喚起軌跡、形狀、DFA、峰終;K6 損失的情感衝擊;K7 讀者模擬器(蒙地卡羅,只報告穩健的低谷與高峰)。
- 參數全是假說;結果是「體驗的結構性前因」,不是品質分數,也沒有經過真人校準。判讀與限制見 [體驗模擬記錄](../設計規範/體驗模擬記錄.md)。
- `檢查.py` 同步檢查讀者知情表的事件 ID 與順序、參數檔是否涵蓋所有標籤,並執行自測。

## 變異測試.py
檢驗體驗指標與既有指標(C2、D1、J1、H3)有沒有「反應」。只讀(擾動只在記憶體裡)。

```
python3 工具/變異測試.py                # 報告
python3 工具/變異測試.py --out F.md      # 寫成檔案
python3 工具/變異測試.py --strict        # 基線與正式工具不一致、或有指標方向相反時結束碼為 1
python3 工具/變異測試.py --draws 40      # 蒙地卡羅抽樣次數
```

- 15 種擾動(刪掉伏筆呼應、打亂章序、插入緩衝章、刪光代價帳、秘密一開場就揭曉、換全新配角……),每種有預期方向的指標與負對照。
- 基線核對:重算的 C2、D1、J1 須與 `劇情量化.py`、`代價帳.py` 一致。
- 它檢查的是**接線,不是效度**;報告末尾有說明。

## 讀者測試包.py
組出「只讀到某一點的讀者」的限知資料包,交給全新的 session 扮演讀者;不呼叫任何模型,只負責組包與純計數。流程、評分規則與偏差見 [讀者測試](../設計規範/讀者測試.md)。

```
python3 工具/讀者測試包.py 取樣                       # 建議切點與轉折事件(確定性取樣)
python3 工具/讀者測試包.py 預測 第二部 12 [--k 3]    # 預測測試包:只含第 12 章以前的事件名稱,最近兩章附簡述
python3 工具/讀者測試包.py 答案 第二部 12 [--k 3]    # 給評分者:實際發生的事,與讀者此時應已感知的伏筆
python3 工具/讀者測試包.py 線索 P2-141               # 線索測試包:給謎底與前文,請找線索並判定公平性
python3 工具/讀者測試包.py 掃描                       # 轉折事件的鋪墊計數(登記伏筆數、設置距離、近 8 章暗示事件)
```

每個子命令可加 `--out 檔案` 寫成檔案(放專案之外或暫存區,不要提交)。包內不含背景事件、標籤、伏筆登記簿、秘密矩陣、吸引力分析與切點之後的內容。
