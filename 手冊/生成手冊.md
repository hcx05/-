# 生成手冊:寫一章的完整流程

這份手冊讓任何一個大語言模型,不靠特定工具或技能,就能把一章小說寫得與既有事實一致。**目標是事實層可重現**:誰在場、發生什麼、誰知道什麼、傷勢持物稱呼數字,不同模型寫同一章不會有出入;文風層只求近似。

## 〇、先決定你的工作模式

| 模式 | 條件 | 做法 |
|---|---|---|
| A 代理模式 | 能讀寫檔案、執行 `python3` | 自己跑工具,走完下面全流程 |
| B 對話模式 | 只能對話,不能執行指令 | 由人(或腳本)執行工具,把**寫作包**貼給你;你照[交付格式](提示/落稿格式.md)輸出區塊,人再用 `工具/落稿.py` 存檔 |

兩種模式用同一套資料與同一套檢查,只是誰來執行指令不同。

## 一、讀什麼,不讀什麼

| 層 | 內容 | 規則 |
|---|---|---|
| T0 常駐 | [AGENTS.md](../AGENTS.md)、[鐵律卡](鐵律卡.md)、本手冊 | 每次任務都讀 |
| T1 寫作包 | `python3 工具/寫作包.py {卷} {章}` 產生的檔 | **寫本章的唯一必讀輸入**;裡面已含大綱、章前狀態、人物卡、場景、稱呼與禁區、前文結尾、風格樣本 |
| T2 受控查詢 | `python3 工具/查詢.py 名稱 --至 {卷}{章}` | 包內資訊不夠時才用;它自動排除未來卷與未來章 |
| 禁區 | `狀態/{本卷以後}結束/`、未來卷的 `成長/`、本章之後的章節大綱與事件描述、`故事線/*/審查報告.md` 類內部評估 | 不讀。讀了就會把後面的劇情寫進現在 |

不要為了「完整」去掃整個倉庫:全庫約 240 萬字,讀不完,而且每個模型讀到的子集不同,結果就不同。

## 二、一章的流程

每一步都有輸入、輸出、通過條件。前一步沒過,不進下一步。

### S-1 看進度
`python3 工具/進度.py`:顯示寫到哪、下一章是什麼、有哪些待決單與待回補事項會影響它、導出檔是否過期。接手任務的第一步。

### S0 取包
`python3 工具/寫作包.py 第一部 2`(上下文小的模型加 `--精簡`)。輸出在 `正文/包/第一部/第02章.包.md`。
**通過**:包頭的預算表沒有異常;你讀完 A 至 I 節。

### S1 場景卡
把本章拆成 4 至 8 個場景(以「＊」分場),存為 `正文/計畫/{卷}/第NN章.場景卡.md`。每個場景一個 `## 場景 N` 區段,含:

```
- 地點:
- 視角:
- 在場:
- 目的與衝突:
- 對應要點: (章節大綱「情節要點」的編號,例 1,2)
- 揭露: (本場讀者或人物新得知的事)
- 禁揭: (不可說破的事)
- 禁揭詞: (本場不得出現的詞,頓號分隔;沒有寫「無」)
- 入場狀態: (人物位置、傷勢、持物、情緒;取自包 C 節)
- 出場狀態:
- 字數預算: (漢字,參考)
```
**通過**:`python3 工具/落稿.py 場景卡 {卷} {章} 場景卡.md` 顯示每個情節要點都被涵蓋。

### S2 逐場景生成
每個場景一次生成,輸入 = 寫作包 + 場景卡 + 上一場景的末段與「場景末狀態」。依[交付格式](提示/落稿格式.md)輸出 `=====正文=====` 與 `=====場景末狀態=====`。範本:[場景生成](提示/場景生成.md)。
`python3 工具/落稿.py 場景 {卷} {章} {場景號} 輸出.txt`
**為什麼分場景**:整章 1 萬多字超過多數模型單次輸出;分場景可從任一處續寫,也容易對照要點。

### S3 組稿
`python3 工具/落稿.py 組稿 {卷} {章}` → `正文/{卷}/第N章_標題.md`。接著把引言行的「視角」「時間」改成貼合正文的寫法。

### S4 機器檢查
`python3 工具/正文檢查.py 正文/{卷}/第N章_標題.md --不要帳本`。**錯誤清零**才往下;提示逐條判斷(多半是誤報,但「已故者出現」「疑似新人名」值得看一眼)。

### S5 修訂(內部,不在輸出中展示)
以讀者身分連續通讀,依序做:
1. **段落與流暢**:普通動作、觀察、反應是否被無故拆成獨立段;資訊是否重複解釋;情緒已由場面傳達後旁白是否又說一遍;人物是否反覆展示同一特質;視角是否越出限知。
2. **節奏診斷**:`python3 工具/正文節奏檢視.py 正文/{卷}/第N章_標題.md {前一兩章}`。警示只是提示,不設合格線。
3. **跨章比對**:對照最近兩三章,同一人物的手勢、口頭禪、反應,同一教誨、回憶、伏筆,交代武學醫術的方式,是否無新意地重演。
4. **敘事厚度複查**(必做一次):重要人物是否有足夠內心活動;看法與情緒變化是否有自然過程;場景是否有可感知的生活環境;對話是否過度集中而缺少敘述承接;重要情境是否被壓得過簡;前幾步是否誤刪了有價值的心理、感官、日常與世情描寫;要補的地方是否真的提供新資訊。發現不足時**補寫**,而不只是刪減。
5. 厚度標準見[寫作規範第三節](../正文/寫作規範.md),寫法見[文筆創作法](../正文/技法/文筆創作法.md)。修訂目的是提高閱讀效果,不是單純變短或變克制。

### S6 獨立複查
**新開一個上下文**(可用同一個模型,但不能帶著寫作時的推理),只給它:寫作包 + 成稿 + 帳本草稿。分兩份報告:
- [事實複查](提示/事實複查.md):逐條列出與寫作包、設定、前文矛盾之處,**每條必須引用來源**。
- [文學複查](提示/文學複查.md):依[文學複查法](../正文/技法/文學複查法.md),看過薄、過滿、重複、視角。

依報告修確實影響閱讀或事實的問題。複查者提出的修改若會動到凍結內容或高層事實,走[優先序與衝突](優先序與衝突.md)。

### S7 帳本
先用 `python3 工具/帳本草稿.py {卷} {章} --寫入` 取得預填一半的草稿(出場者列表、數字候選、疑似新人名、要點對照骨架),再依[帳本說明](../正文/帳本/README.md)與[模板](../正文/帳本/模板.帳本.md)補完;只記正文確立的事實,不知道寫「未載」。草稿裡的 `(待填)` 沒補完會被檢查器擋下。
`python3 工具/落稿.py 帳本 {卷} {章} 輸出.txt`(自動重建累積狀態與索引)。若直接編輯帳本檔,之後執行 `python3 工具/帳本合併.py` 與 `python3 工具/建索引.py`。
**通過**:`python3 工具/正文檢查.py 正文/{卷}/第N章_標題.md` 無錯誤(含帳本格式、要點對照、回補路徑)。

### S8 回補與影響掃描
1. `python3 工具/回補清單.py` 列出待回補的新增事實及建議寫入位置。
2. `python3 工具/影響掃描.py {卷} {章}`(這是**維護步驟**:它會印出後文大綱的片段,可能含劇透,請在寫作上下文之外執行,例如交給另一個上下文或另一次工作階段,只把「需要補丁的章與要改的句子」帶回來)找出**之後章節的大綱與事件描述**裡提到本章新物件、專名、稱呼的地方,核對是否與已定稿正文一致;不一致時正文為準,在該章大綱加補丁段落(標題含「改版」或「增補」)。
3. 帳本「新增事實」中標「待回補」的,寫回對應設定檔(角色記憶、場景建模、勢力、事實登錄、伏筆登記簿),再把回補欄改成 `已回補→路徑`。與大綱出入較大者,更新[正文 README](../正文/README.md) 的進度表。若動到凍結內容,走變更傳播。

### S9 全量檢查與提交
`python3 工具/檢查.py`、`python3 工具/測試.py` 全綠。把正文、帳本、累積狀態、索引、設定回補一起提交。

## 三、停止條件

遇到下列情形**停下來**,不要硬寫:
- 寫作包裡兩處資料互相矛盾,且依[優先序](優先序與衝突.md)判不出唯一答案;
- 場景需要未設定的能力、毒物、療法、重要人物或歷史事件;
- 寫作包要求的內容與稱謂表、揭露節點衝突(例如大綱要求某角色說出尚未可出現的名字);
- 正文檢查報錯,而修正要靠改動凍結內容。

停下來的做法:開待決單(`=====待決=====` 區塊或直接寫 `正文/待決/Q-xxx.md`),寫明暫行做法,繼續寫不受影響的部分。

## 四、改寫、潤稿既有章節

1. 先取該章的寫作包(它會取「截至該章」的資料)與現有正文。
2. 保持原文的重要資訊、事件因果、視角、結局;不以潤稿之名新增重大事件、過往、能力或伏筆。
3. 改完後從 S4 起重走,並更新該章帳本與其後章節帳本中受影響的「章末人物狀態」。

## 五、常見失敗與對策

| 失敗 | 原因 | 對策 |
|---|---|---|
| 提前說出尚未揭露的名字或秘密 | 把作者知道的寫成角色知道的 | 看包 F 節;S4 的揭露節點檢查 |
| 傷勢、持物、位置接不上前章 | 沒讀章前狀態 | 包 C 節為準;要改變須在情節中交代 |
| 數字漂移(人數、天數、銀兩) | 憑印象寫 | 包 C 節「前章數字事實」與帳本 |
| 同一手勢、口頭禪反覆 | 把聲口卡當表演清單 | 聲口是背景,不是每次登場的任務;S5 跨章比對 |
| 長章寫到後面變薄 | 一次生成整章 | 分場景生成,每場景有字數預算 |
| 帳本寫成劇情摘要 | 沒有區分「事實」與「過程」 | 帳本只記之後可能被引用的事實 |
| 把推測當既定設定 | 資料不足時順手補 | 停止條件;開待決單 |
