# 劇情基準

劇情是這個專案的**骨幹**:世界、人物、事件、秘密、伏筆、力量體系都在這一層定義;小說正文只是其中一個輸出,日後動畫、遊戲等也從同一層取用。本文件回答三件事:

1. 怎麼把劇情當成一個系統來**量測**(指標與定義);
2. 標竿作品(金庸、鄭丰)有哪些**可查證**的結構資料,證據到什麼程度;
3. 劇情做到什麼程度才算**夠好**(驗收標準)。

> 量測由 `python3 工具/劇情量化.py` 執行;本文件是指標、基準與驗收標準的**正本**,工具只讀取其中的「基準區間(機器讀取)」。
> 本文件不討論文筆;文字層見 [正文/寫作規範](../正文/寫作規範.md)。

## 一、系統模型:劇情骨幹的軟體工程對照

這張對照表是**設計**(本專案自己的整理),不是標竿作品的結論。用途是把「劇情好不好」拆成可以分別檢查的部分。

| 劇情元素 | 軟體工程概念 | 本專案正本 | 對應指標 |
|---|---|---|---|
| 世界規則、硬規則 | 約束與不變量(constraints) | [事實登錄](事實登錄.md) | H(硬不變量) |
| 人物 | 實體(entity) | `角色/` | B |
| 勢力 | 模組或服務(module) | `勢力/` | F |
| 事件 | 事務(transaction):有不可變 ID、前置與後置狀態 | `故事線/{卷}/時間線.md`、`事件描述.md`、`凍結.md` | A、D、G1 |
| 章 | 視圖(view):同一批事件的呈現單位 | `故事線/{卷}/章節/` | A、D2 |
| 秘密與知情 | 共享狀態加存取控制(誰在何時能讀到什麼) | [秘密知情矩陣](../狀態/秘密知情矩陣.md) | C1 |
| 伏筆 | 未完成的承諾(open promise),需要被回收,長距離的需要保活 | [伏筆登記簿](../狀態/伏筆登記簿.md) | C2、H1 至 H3 |
| 力量體系 | 規則引擎與資源平衡(難度曲線) | `武學設定/總綱/戰力基準.md` | E |
| 節奏標籤 | 負載曲線 | [標籤表](標籤表.md) | D |
| 卷與主篇 | 里程碑與發佈 | `故事大綱/`、`故事線/{卷}/大綱.md` | A |
| 凍結與變更傳播 | 介面凍結與相依更新 | [建檔架構與順序](建檔架構與順序.md) | `工具/檢查.py` |
| 小說、動畫、遊戲 | 不同的前端(presentation) | `正文/` 等 | G(改編就緒度) |

核心取捨:**事件是資料,章與媒介是呈現**。因此骨幹層不預設敘事形式([開發標準](../開發標準.md) 第 8 項),也要保證任何前端都能取到它需要的欄位(指標 G)。

## 二、指標定義

每項指標都說明資料從哪裡來。除標明「基準區間」者外,指標只列數字,不下判斷。

| ID | 指標 | 定義 | 資料來源 |
|---|---|---|---|
| A1 | 每部章數 | 各部章節大綱的檔案數 | `故事線/{卷}/章節/` |
| A2 | 章均字數(萬) | 各部章節大綱預計字數的合計 ÷ 章數 | 章節 README |
| A3 | 演出事件/章 | 章節欄為「第 N 章」的事件數 ÷ 章數 | 時間線 |
| B1 | 男女主佔邊 | 角色共現圖中,至少一端是男女主的邊所佔比例 | 事件描述的出場角色 |
| B2 | 去除男女主後的連通塊 | 拿掉男女主後,配角圖還剩幾塊;塊越多代表世界越依賴男女主連結 | 同上 |
| B3 | 群像規模 | 演出事件出場 ≥2 次的角色數 | 同上 |
| C1 | 資訊差庫存 | 各時點「男主知而女主不知」「女主知而男主不知」的秘密數 | 知情矩陣 |
| C2 | 伏筆距離 | 設置事件到第一個回收事件的章數(跨卷累計排序);另算「距離 ≥40 章卻只有單一設置點」者 | 伏筆登記簿 |
| D1 | 負載分布 | 事件標籤依標籤表分為緩衝、推進、重三類的比例;最長連續無緩衝段(**標籤口徑**:事件帶任一緩衝類標籤即算有緩衝,與標籤表、`標籤檢視.py` 一致;另列嚴格口徑,要事件標籤全是緩衝類才算,僅供參考);第一個「重」的位置;「重」的十等分分布 | 時間線、標籤表 |
| D2 | 視角平衡 | 章節大綱「視角」欄中,只男主、只女主、交錯、群像的章數 | 章節大綱 |
| D3 | 尾段密度 | 各部末三分之一章的事件密度 ÷ 全部平均 | 時間線 |
| E1 | 難度曲線 | 各卷結束時男主 L,與本卷出場者中的最高 L | 角色狀態快照 |
| F1 | 朝堂傾向 | 事件標籤含權謀、或場景為朝堂類、或朝廷類勢力出場;依 DEC-074 對廟堂的定義,黑衣衛、血月教等不計入 | 時間線、事件描述 |
| G1 | 事件契約欄位覆蓋 | 事件描述含「目標、衝突、結果」欄位的比例,另算「重」類事件的覆蓋率(見第五節) | 事件描述 |
| G2 | 場景資料 | 演出事件中場景標「待建」的事件數 | 事件描述 |
| G3 | 角色視覺資料 | 出場 ≥3 次的角色中,設定檔沒有「外表」的人數 | 角色設定 |
| H1 | 伏筆有回收 | 每條伏筆都有可解析的回收事件 ID | 伏筆登記簿 |
| H2 | 伏筆有設置 | 每條伏筆的設置事件可解析,或標明典籍、世界設定 | 同上 |
| H3 | 回收不早於設置 | 回收事件的章不得早於設置事件的章 | 同上 |
| H4 | 無未裁定的待決 | 各卷大綱「待決」表中沒有未標「已定」的項目;移交正文階段者另計 | 卷大綱 |
| I1 | 可預測度 | 全新 session 只讀到某切點時,預測接下來 K 個事件的得分 ÷ K(命中 1、部分 0.5、未中 0);同卷多切點取平均 | 讀者測試(見[讀者測試](讀者測試.md)),手動記錄 |
| I2 | 轉折鋪墊 | 轉折事件經線索測試判為「公平」者 ÷ 測過的轉折數;另有純計數的鋪墊掃描(登記伏筆數、設置距離) | 線索測試、`讀者測試包.py 掃描` |
| I3 | 伏筆可感度 | 讀者列出的懸問中,對應到「應已感知的伏筆」的條數 ÷ 該表條數 | 預測測試附帶題 |
| J1 | 主角空窗 | 男女主任一承擔不可逆損失的章之間,最長連續章數 | [代價帳](../狀態/代價帳.md)、時間線 |
| J2 | 重類帳目覆蓋 | 標籤帶死亡、悲劇的演出事件中,代價帳有帳目者的比例;另列無帳目的候選 | 同上 |
| J3 | 損失分布 | 男女主損失的類別與可逆性計數,各卷不可逆損失筆數 | 同上 |
| K1 | 讀者知情 | 戲劇反諷庫存(讀者確知、男女主至少一人未知的秘密數)與謎團庫存(讀者見過暗示、尚未確知的秘密數),逐章 | [讀者知情](../狀態/讀者知情.md) |
| K2 | 開放問題庫存 | 逐章已設置未回收的伏筆,加上未被伏筆涵蓋的謎團;另算依記憶保留打折的有效數 | 伏筆登記簿、讀者知情 |
| K3 | 記憶保留 | 伏筆回收當章讀者仍記得的機率 R = exp(−空檔 / S),S 隨呼應次數增長;角色重返同理 | 伏筆登記簿、時間線、[體驗參數](體驗參數.md) |
| K4 | 事件索引轉換負荷 | 逐章累計時間、空間、主角、配角的轉換,加上新角色、新場景、新伏筆的首次出現(意圖、因果無資料欄,未計) | 時間線、事件描述 |
| K5 | 效價與喚起軌跡 | 標籤換算的逐章效價與喚起;形狀比對、DFA 標度指數、峰終、連續低/高喚起 | 時間線、體驗參數 |
| K6 | 損失的情感衝擊 | 代價帳每筆 = 類別基礎值 × 讀者對逝者的依附度 × 可逆性係數;逐章總和與無損失空窗 | 代價帳、時間線 |
| K7 | 讀者模擬器 | 逐章投入(好奇、喚起、損失、負荷、疲勞、無聊),對參數範圍蒙地卡羅抽樣,只報告穩健的低谷與高峰 | K1 至 K6 |

K 組是**體驗的結構性前因**,不是品質分數:全部參數是假說([體驗參數](體驗參數.md)),沒有外部基準、不設門檻,只列分布與位置;指標有沒有反應由 `python3 工具/變異測試.py` 檢查,是否等於讀者感受要靠真人校準(見 [體驗量化研究](體驗量化研究.md)、[體驗模擬記錄](體驗模擬記錄.md))。

## 三、證據:標竿作品

證據等級:

- **A**:作者本人的專訪或出版社的出版資訊(一手或接近一手);
- **B**:學術論文或專書的摘要、目錄(只看到摘要,未見全文);
- **C**:評論、網路文章、百科與問答類網頁(二手,互相可能衝突);
- **無**:查不到的,一律寫「未查得」,不補。

查證方式與限制:以下全部來自網路搜尋結果的摘要,**沒有讀過作品全文**,也沒能開啟頁面全文(網路政策限制)。因此這裡只放「作品的公開規格」與「研究與專訪中明確寫出的結構性結論」,不放我自己對劇情的解讀。

### 證據能支持什麼、不能支持什麼

- **能支持**:篇幅與回數的量級;「雙主角、群像規模、男主成長從先天優越轉向後天努力」這類定性設計方向;已有人用功能序列做過結構統計(方法可借)。
- **不能支持**:轉折點的位置、伏筆距離、角色出場分布、主副線分工等**需要逐回標註原著**才有的數字。這些我沒有、也不編造(見第六節)。
- 因此第四節的「基準區間」目前只有 A1、A2 兩條,其餘指標在驗收標準中改用**專案自訂門檻**(明確標示,不假裝來自標竿)。

## 五、「夠好」的驗收標準

軟體工程的做法是「完成的定義」(definition of done):分層列出,**不靠感覺**。

| 層 | 內容 | 判定方式 | 目前狀態 |
|---|---|---|---|
| T1 硬不變量 | `python3 工具/檢查.py` 通過;`劇情量化.py` 的 H1 至 H4 皆無違反 | 自動,必須 0 項 | 已達成 |

### 事件契約(草案,待確認)

動畫與遊戲要從骨幹取用,事件至少要能回答「這個事件為什麼存在、卡在哪、結束後世界變成什麼樣」。目前事件描述有序號、時間、章節、場景、描述、出場角色,但這三樣只藏在描述句裡:

- **目標**:誰想做到什麼;
- **衝突**:什麼東西擋著;
- **結果**:事件結束後的狀態變化(誰得知了什麼、誰受傷或死亡、物件或關係的變動)。

這是軟體工程裡「前置條件、後置條件」的對應。建議先補「重」類事件與序卷的演出事件,再逐步擴大;補寫時不改事件 ID、時間、章節與出場者,只新增欄位。

## 六、尚未量化的部分與標註協議

要得到標竿作品的轉折點位置、伏筆距離、出場分布等數字,必須對原著**逐回做結構標註**。這需要有原著文本可讀;本次環境查不到全文,所以沒有做。標註格式(只記結構事實,不抄原文):

每部作品一個檔案,每回一列:

| 欄位 | 內容 |
|---|---|
| 回 | 回數 |
| 事件數 | 該回發生的主要事件數 |
| 視角人物 | 該回的視角或焦點人物 |
| 新角色 | 該回首次登場的有名字角色 |
| 重大轉折 | 有則標,並註明類型(揭露、反轉、死亡、戰爭等,沿用[標籤表](標籤表.md)) |
| 伏筆 | 該回設置或回收的伏筆,各以簡短編號對應 |

標註完成的作品放在 `設計規範/劇情基準/標註/` 下,再由 `劇情量化.py` 擴充讀取,用同一組指標比較。若你能提供合法持有的原著文本供本地分析,我可以先寫統計腳本(章長、角色共現、出場分布),再由人工補標轉折與伏筆。

## 七、使用方式

- 改了劇情(事件、時間線、章節大綱、伏筆、秘密)後:`python3 工具/劇情量化.py` 看 H 節有沒有違反,`python3 工具/代價帳.py` 看主角的代價分布(有新的明文損失先補進[代價帳](../狀態/代價帳.md)),再執行 `python3 工具/檢查.py`。
- 改了劇情後也可以跑 `python3 工具/體驗模擬.py`(K 組:資訊差、開放問題、記憶保留、轉換負荷、情緒軌跡、損失衝擊、讀者模擬器)看哪些章段、哪些伏筆在模型下顯得吃力;改了參數或工具後跑 `python3 工具/變異測試.py` 確認指標仍有反應。這些是診斷,不是驗收條件。
- 要判斷「套路不套路、轉折有沒有鋪墊」:照[讀者測試](讀者測試.md)用 `工具/讀者測試包.py` 組包,交給全新的 session。這類結果是代理指標,不是驗收的充分條件。
- 要改關鍵事件或設計缺口的解法:先做[選項對照](選項對照.md)。
- 凍結前:T1 至 T4 都要有結論;凍結後再改走變更傳播。
- 指標、基準或驗收標準有調整:改本文件,並在設計決定記錄新增一條。
