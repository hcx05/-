# 建檔架構與順序

本文件說明這部作品「有哪些檔案層、彼此如何依賴、為什麼要照這個順序建、改動時如何傳播」。具體步驟見 [開發順序](../開發順序.md),規範與清單見 [開發標準](../開發標準.md)。

## 一、架構總覽:十層

| 層 | 名稱 | 位置 | 內容 | 建立時機 |
|---|---|---|---|---|
| L0 | 規則層 | `設計規範/`、`開發標準.md`、`開發順序.md`、`工具/` | 事實登錄、設計決定、術語、ID 體系、單一來源、標籤表、個性轉變記錄、檢查腳本 | 作品初始化,隨卷增補 |
| L1 | 世界層 | `世界設定/世界觀/`、`武學設定/` | 世界觀、武學與靈能體系、戰力基準、典籍 | 作品初始化,隨卷增補 |
| L2 | 作品骨架 | `故事大綱/` | 一句話故事、規模、各部宏觀大綱、占比與分線 | 作品初始化 |
| L3 | 主角層 | `角色/男主/`、`角色/女主/` | 暫定名、ID、初始個性、天賦 | 作品初始化 |
| L4 | 卷骨架 | `故事線/{卷}/` | 大綱、時間線(含標籤)、節奏檢視、年齡表、吸引力分析、凍結紀錄 | 每卷開始 |
| L5 | 實體層 | `角色/主要角色/`、`勢力/`、`世界設定/場景設定/` | 角色設定、勢力、場景建模,以及 ID 與戰力登記 | 每卷(由 L4 決定需要誰) |
| L6 | 事件層 | `故事線/{卷}/事件描述.md`、`章節/` | 事件描述(樞紐)、章節大綱 | 每卷(實體齊備後) |
| L7 | 紀錄層 | `角色/**/成長/` | 記憶、武學、感情、個性轉變 | 每卷(由事件驅動) |
| L8 | 狀態層 | `狀態/` | 卷末快照、秘密知情矩陣、伏筆登記簿 | 每卷結束 |
| L9 | 驗證層 | `工具/檢查.py` | 自動一致性檢查 | 每個階段與提交前 |

## 二、依賴關係(誰依賴誰)

```
L0 規則 ─────────────────────────────────────────────────┐
L1 世界 ──┐                                              │ (全程約束)
L2 骨架 ──┼→ L4 卷骨架 ─→ L5 實體 ─→ L6 事件 ─→ L7 紀錄 ─→ L8 狀態 ─→ 下一卷的 L4
L3 主角 ──┘      │            ↑          │                          ↑
                 └ 吸引力檢視 ┘          └ 事件 ID 是各層共同的引用樞紐
L9 驗證:對以上每一層的一致性做自動比對
```

關鍵依賴:
- **L4 → L5**:時間線與事件決定「需要誰、需要哪個組織、需要哪個地點」,所以實體層必須在卷骨架之後。
- **L5 → L6**:事件描述的出場者、場景要附連結,實體必須先存在。
- **L6 → L7**:每條紀錄都引用事件 ID,事件定案後才能寫紀錄。
- **L7 → L8**:狀態快照是紀錄的彙總(派生資料),不是另一份獨立設定。
- **L8 → 下一卷 L4**:上一卷的結束狀態是下一卷的起始狀態。
- **事件 ID 是樞紐**:時間線、事件描述、章節大綱、所有紀錄、伏筆登記簿、個性轉變都用同一組 ID 連動。

## 三、為什麼是這個順序(邏輯)

1. **規則先於內容**:硬規則與用詞若不先固定,後面每一層都會各寫各的。
2. **由大到小**:先決定「這一卷要說什麼」,再決定「發生哪些事」,最後才是「誰在什麼時候知道什麼」。
3. **骨架先於實體**:先排事件與節奏,才知道需要哪些角色與場景,避免白建檔。
4. **標籤先於內容**:節奏與感情線的失衡,在只有標籤的階段修,成本最低。
5. **吸引力檢視放在骨架階段**:這時改動只牽涉大綱、時間線與標籤;若等實體與紀錄都建好才檢視,每個改動都要傳播到多處(序卷便是如此:加入雲裳、白眉老祖後,要重新產生多處「相關事件」)。
6. **凍結點**:吸引力檢視與年齡表通過後凍結事件骨架(事件 ID、出場者、時間);凍結後的任何改動都走「變更傳播」。
7. **實體先於引用**:連結指向不存在的檔案,等於資料不完整。
8. **事件驅動紀錄**:以事件為單位同時更新所有出場者,才能保證雙向感情、資訊流與個性轉變一致。
9. **狀態最後彙總**:快照由紀錄匯總,只在紀錄穩定後產生。
10. **驗證每階段做**:錯誤越早抓越便宜。

## 五、變更傳播(凍結後如何改動)

凍結後若要改動,先判斷改動類型,再依表更新所有衍生處,最後執行 `python3 工具/檢查.py`。

| 改動 | 必須同步更新 | 檢查腳本能抓到 |
|---|---|---|
| 事件出場者增減 | 事件描述 → 該角色的記憶、武學、感情「相關事件」→ 章節大綱 → 狀態與知情矩陣 | 事件覆蓋、感情對稱 |
| 事件新增或刪除 | 時間線(新 ID,不重編)→ 事件描述 → 章節大綱 → 節奏檢視 | 事件連號、章節一致、節奏檢視過期 |
| 事件時間或順序 | 時間線 → 年齡表 → 事件描述 → 紀錄 | 年齡、已故 |
| 角色年齡 | 年齡表 → 設定檔 → 狀態表 | 年齡 |
| 角色戰力 | 設定檔 → 成長/武學 → 狀態表 → 戰力基準 | 戰力 |
| 角色死亡或生死 | 狀態表 → 後續事件出場者 → 設定時點 | 已故 |
| 新增角色 | 設定、ID 對照、戰力基準、事件、紀錄 | ID、事件 |
| 角色個性轉變 | 轉變日誌 → 狀態表當前個性;必要時記憶與感情 | 個性 |
| 秘密的知情者變動 | 知情矩陣 → 相關角色記憶 | 無(需人工) |
| 場景改動 | 場景建模 → 事件描述 → 章節大綱 | 連結 |
| 標籤或感情線 | 時間線 → 重新產生節奏檢視 | 標籤 |
| 硬規則改動 | 先在設計決定記錄登記 → 事實登錄 → 所有受影響設定 | 術語(部分) |
| 術語改名 | 術語表 → 全域替換 | 術語 |
