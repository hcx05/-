# 選項對照

改劇情或補關鍵事件時,不要只寫一條路就交付。對**會影響後續的決定**(改轉折、增刪重類事件、處理 DEC-074 的政治弧、補長距伏筆的呼應點),先寫出三種走法並列比較,再選一個,留下理由。目的是對抗「第一個合理的想法就是最終版本」,讓代價與可預測度成為決定的依據。

## 什麼時候要做

- 要改動凍結事件的實質、順序或章節時;
- 為 `劇情量化.py`、`代價帳.py` 或讀者測試量出的缺口設計解法時;
- 新增「重」類事件、轉折事件時。

小幅文字調整、補登記、不改變事件實質的補寫,不需要。

## 做法

在 `設計規範/選項對照/` 新增 `OPT-編號_主題.md`(編號依序),用下列結構。`python3 工具/檢查.py` 會檢查必填項。

````markdown
# OPT-001 主題

- **起因**:哪個量測缺口或要求觸發(指標編號或 DEC)
- **涉及事件**:P1-029、P1-030(逗號或頓號分隔,須存在於時間線)
- **日期**:YYYY-MM-DD

## 方案 A:一句話名稱
- **做法**:...
- **主角付出的代價**:...(對照 狀態/代價帳.md 的類別與可逆性)
- **可預測度**:低 / 中 / 高,一句話理由(必要時附讀者測試結果)
- **後續分支**:它打開或關上哪些後續事件
- **變更範圍**:要動的凍結內容(事件、章節、伏筆、知情矩陣)

## 方案 B:...(同上五項)

## 方案 C:...(同上五項)

## 結論
- **選擇**:A / B / C / 其他
- **理由**:...
- **DEC**:DEC-xxx(寫入設計決定記錄後填;尚未寫入填「待補」)
````

## 寫方案的規則

1. **三個方案要真的不同**,不是同一條路的三種措辭。至少有一個方案要讓主角付出比最顯而易見的走法更大的代價,至少有一個要讓讀者不容易猜到。
2. **不可逆的代價要明說**,並在選定後補進代價帳。
3. **可預測度先自評,有條件時用[讀者測試](讀者測試.md)的預測包驗證**:把方案寫成「接下來的事件」,看測試者猜不猜得中。
4. 被否決的方案與理由保留在檔案中,日後有人想回頭改時有跡可循。
